# FAQ & Troubleshooting

## General Questions

### What is binary obfuscation?

Binary obfuscation is the process of transforming a compiled executable to make it harder to reverse engineer, while preserving its original functionality. Unlike source-code obfuscation, binary obfuscation works on already-compiled machine code.

### Does obfuscation make my program uncrackable?

No. Obfuscation raises the bar for reverse engineering but does not make it impossible. A determined analyst with sufficient time and tools can still understand the program. ObfuGuard is designed to significantly increase the effort required, not to provide absolute protection.

### Will obfuscation break my program?

ObfuGuard is designed to preserve program behavior. However, some edge cases may cause issues:
- Programs using exception handling with specific stack layouts
- Programs that self-inspect their own code sections
- Programs with integrity checks on their own binary

Always test obfuscated output before deployment.

### Can I apply both CFF and junk code to the same binary?

You can apply them sequentially (e.g., junk code first, then CFF), but the second pass requires a PDB file for the intermediate binary. Since obfuscated binaries don't have matching PDBs, combining both modes on the same binary requires manual RVA specification.

## Technical Questions

### Why does CFF only support 64-bit PE?

The CFF engine uses `rax` as the state variable for the dispatcher and relies on 64-bit specific instruction encoding patterns. Supporting 32-bit would require a separate implementation with different register allocation and addressing modes.

### Why do some functions get skipped during CFF?

Functions containing jump tables (typically generated by `switch` statements) are automatically skipped. Jump tables use indirect addressing (`jmp [rax*8 + table_base]`) that would break when blocks are shuffled, because the table entries reference original addresses.

### What is the `.0Cff` section?

It's a new PE section created by ObfuGuard to hold the flattened function code. The name starts with `.0` to place it early in alphabetical section listings. It's allocated at 10 MB to accommodate all relocated functions.

### What is the `.0Dev` section?

It stores the obfuscated entry point code, encoded with XOR and rotation to prevent easy identification of the program's starting point.

### Why does junk code injection create one section per function?

Each function is relocated to its own section to:
- Isolate function relocations from each other
- Simplify address fixup calculations
- Allow independent section management

The trade-off is the PE section count limit (~96 maximum).

### What happens if my binary has too many functions for junk code injection?

The tool automatically calculates the maximum number of injectable functions based on the current section count. Functions are prioritized by size (largest first), and the tool reports how many were actually injected vs. how many were requested.

## Build Issues

### vcpkg packages won't install

Make sure vcpkg is properly bootstrapped and integrated:
```powershell
cd vcpkg
.\bootstrap-vcpkg.bat
.\vcpkg integrate install
```

Then retry the install commands with the `:x64-windows` triplet.

### Build fails with missing headers

Ensure all vcpkg packages are installed for the correct triplet:
```powershell
vcpkg list
```

You should see `capstone`, `keystone`, `lief`, `asmjit`, and `zydis` all with `:x64-windows`.

### Link errors with DbgHelp

`dbghelp.lib` is linked via `#pragma comment(lib, "dbghelp")` in the source. Ensure the Windows SDK is properly installed with your Visual Studio 2022 installation.

## Runtime Issues

### "Error: File does not exist"

- Check the file path for typos
- If the path contains spaces, wrap it in quotes when providing it to ObfuGuard
- Ensure the PDB file is in the same directory as the PE file with the same base name

### "Error: Control Flow Flattening only supports 64-bit PE files"

You provided a 32-bit PE file. Use junk code injection (mode 2) instead, which supports both 32-bit and 64-bit.

### "Not a valid PE file (Missing MZ signature)"

The file is not a valid Windows PE executable. Ensure you're providing a `.exe` file, not a `.dll`, `.obj`, or other file type.

### Obfuscated binary crashes

Possible causes:
1. A blacklisted function was somehow included (check the function blacklist)
2. The program uses exception handling that conflicts with CFF's stack manipulation
3. The program performs self-integrity checks

Try using junk code injection instead of CFF, or manually select specific functions in manual mode.

### Obfuscated binary output differs from original

1. Run `match_check.py` to confirm
2. Check if the program uses non-deterministic behavior (random numbers, timestamps, thread scheduling)
3. Check if the program inspects its own memory layout

### "Warning: No functions found through PDB"

The PDB file may not contain function symbols. This can happen if:
- The PDB was stripped
- The binary was compiled without debug information (`/Zi` flag missing)
- The PDB file doesn't match the PE file (different build)

## Performance Questions

### How much does CFF slow down my program?

Typically < 5% overhead for most programs. The dispatcher transitions add a few instructions per basic block transition. Programs with very tight loops may see more impact.

### How much does junk code injection slow down my program?

Minimal overhead. The trampoline is a single `jmp` instruction, and junk instructions are lightweight (NOPs, identity operations). The main cost is a potential increase in instruction cache misses due to code relocation.

### How much does obfuscation increase binary size?

- **CFF:** The `.0Cff` section adds up to 10 MB to the binary, though typically much less is used
- **Junk code:** Each injected function adds a new section (~4 KB minimum), so size growth depends on the number of functions processed

## Tool Compatibility

### Does ObfuGuard work with .NET/managed executables?

No. ObfuGuard only works with native PE binaries (compiled C, C++, Rust, etc.). .NET assemblies use IL bytecode, not native machine code.

### Does ObfuGuard work with packed/encrypted binaries?

No. The binary must be in its original, unmodified PE format with valid section mappings. Packed binaries have compressed/encrypted code sections that ObfuGuard cannot parse.

### Can I use ObfuGuard on DLLs?

The current version is designed for `.exe` files. DLL support would require additional handling for export tables, relocation tables, and entry point semantics.
